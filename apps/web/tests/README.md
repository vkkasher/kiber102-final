# Проверки web

`npm test` запускает проверки календаря, сетевых ошибок, цен, допустимых Origin и нетипизированных действий агента, а также компонентные проверки форм и изображений. `npm run lint` проверяет TypeScript, доступность JSX и React Hooks без подавления предупреждений. `npm run generate:api` обновляет типы из OpenAPI. Свежие результаты и границы проверки описаны в [приёмке](../../../docs/acceptance.md).

Обычные Playwright-тесты используют `WEB_TEST_URL`, по умолчанию `http://127.0.0.1:3000`. Сценарии изменения событий из `isolated-flows.spec.ts` выполняются только с `ISOLATED_WEB_E2E=1` и `WEB_TEST_URL=http://127.0.0.1:3100`.

Для этих сценариев поднимите отдельный API на **127.0.0.1:8100**, задав отдельный SQLite-файл `.local/web-e2e-<имя>.db`, отдельные ADMIN_PASSWORD/ADMIN_SESSION_SECRET и TRUSTED_PROXY_SECRET длиной не менее 32 символов. Разрешите источник example.org только в окружении этого API. Отдельный Next dev на **127.0.0.1:3100** должен использовать API_INTERNAL_URL=http://127.0.0.1:8100, WEB_PUBLIC_URL=http://127.0.0.1:3100 и тот же TRUSTED_PROXY_SECRET. Рабочие `.env` и базу каталога не меняйте.

Для проверок ролей до запуска отдельного API задайте три учётные записи. В PowerShell из корня проекта, после задания тестового ADMIN_PASSWORD:

```powershell
$env:ADMIN_ACCOUNTS_JSON = & .venv/Scripts/python.exe -c "import os,json; from apps.api.app.security import hash_password; print(json.dumps({r:{'password_hash':hash_password(os.environ['ADMIN_PASSWORD']),'role':r} for r in ('admin','moderator','viewer')}))"
$env:CORS_ORIGINS = 'http://127.0.0.1:3100'
$env:SOURCE_ALLOWED_HOSTS = 'example.org'
```

Из корня проекта в окружении тестового администратора задайте API_TEST_URL=http://127.0.0.1:8100 и ISOLATED_WEB_E2E=1, затем выполните `.venv/Scripts/python.exe apps/web/tests/seed-isolated.py`. Скрипт готовит 105 записей с явной меткой TEST_DATA. Три из них доступны только в отдельном тестовом каталоге. После этого из apps/web выполните `npm run test:e2e` с WEB_TEST_URL=http://127.0.0.1:3100, ISOLATED_WEB_E2E=1 и тестовым ADMIN_PASSWORD.

Эти тесты проверяют создание, импорт, проверку, публикацию, отмену, очередь обращений и подтверждение действия агента. Они не являются приёмкой реальных исходных данных. По окончании остановите оба тестовых процесса.

Полный текущий набор содержит 43 Playwright-сценария в десяти файлах, включая регрессии поиска, подписки, виджета и ошибок карточки. `tests/accessibility.spec.ts` можно запускать на production как отдельную проверку без мутаций. Он проверяет публичные маршруты, включая страницу материалов на четырёх ширинах, меню, reduced motion, iframe без Cookie и фактический GET через Swagger UI, включая полную блокировку внешних запросов. `admin-accessibility.spec.ts`, `planner-form.spec.ts` и `feedback-resilience.spec.ts` защищены условием отдельного контура, как и сценарии изменения событий. Список набора из `apps/web` показывает `npx playwright test --list`, число пройденных проверок зависит от выбранного контура и отмечается отдельно.

Для резервной записи браузера из корня проекта выполните `node apps/web/tests/record-demo.mjs`. По умолчанию записывается настоящий каталог http://127.0.0.1:3000 с целевой длительностью 300 секунд при разрешении 1280×800. Можно задать `--url`, `--duration` от 30 до 3600 секунд и `--output` с путём к WebM. Скрипт отказывается записывать TEST_DATA, не входит в админку и не меняет события. Для запуска кодировщика предусмотрены пять дополнительных секунд реальной записи. Рядом с видео сохраняется JSON со временем этапов и проверенной фактической длительностью медиа. Telegram в запись не входит.
