# Развёртывание

Основной серверный вариант использует [compose.yaml](../compose.yaml), PostgreSQL 17, FastAPI, Next.js, worker и Telegram-бота. Локальная видеокарта и веса Qwen для DeepSeek не требуются. Этот документ описывает Compose-вариант. Отдельный временный экземпляр владельца с SQLite и systemd описан в [паспорте размещения](temporary-hosting.md).

## Подготовка сервера

Нужен Linux x86_64 с Docker Engine и Compose, свободное место для образов, БД, raw и резервных копий. Размер памяти и скорость сборки проверяются на выбранном сервере. Фактический минимум для всего проекта на существующем сервере пока не подтверждён. Для ограниченной RAM предпочтительна сборка образов на отдельной машине с последующей передачей в согласованный registry.

Выберите свободную папку проекта, порты и имя сайта. Не заменяйте уже работающие службы, не освобождайте их порты принудительно и не удаляйте соседние volumes. Compose по умолчанию публикует web на `127.0.0.1:3000`, API на `127.0.0.1:8000`. При занятых портах изменяется только левая часть mappings в согласованном override. PostgreSQL наружу не публикуется.

## Конфигурация и запуск

Команды этого раздела выполняются в Bash из корня проекта.

```bash
cp .env.example .env
chmod 600 .env
```

Заполните четыре разных секрета `POSTGRES_PASSWORD`, `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET`, `TRUSTED_PROXY_SECRET`. Для генерации одного значения можно использовать `openssl rand -hex 32`. Установите `WEB_PUBLIC_URL`, `WEB_URL` и `CORS_ORIGINS` в точный HTTPS-адрес выбранного сайта. Токен бота и ограниченный ключ OpenRouter перенесите защищённым способом, без shell history. Рабочая конфигурация в репозиторий не входит. Секреты нового экземпляра создаются оператором, доступы к внешним сервисам передаются отдельно по [инструкции](delivery.md). Для проверки данных без приватного состояния приложен [снимок каталога](../data/README.md). До включения серверного бота остановите другую polling-копию.

Compose передаёт `WEB_PUBLIC_URL` в сборку web через `build.args` и в окружение контейнера. Адрес нужен и при сборке статических метаданных. При отдельной предварительной сборке web передайте `--build-arg WEB_PUBLIC_URL=https://ваш-домен`. При смене внешнего Origin пересоберите web и пересоздайте сервисы командой запуска ниже. Простой перезапуск старого образа не обновляет уже собранные адреса.

```bash
docker compose config --quiet
docker compose up --build -d
docker compose ps
curl --fail http://127.0.0.1:8000/api/v1/health
curl --fail -I http://127.0.0.1:3000/
```

Backend перед приёмом запросов выполняет `alembic upgrade head`. При первом запуске база пуста. Рабочие записи переносятся отдельно. SQLite не конвертируется в PostgreSQL изменением DATABASE_URL. До серверного показа нужен проверенный перенос данных через импорт/модерацию или отдельная миграция данных с проверкой UUID, происхождения, статусов и связей.

Простая остановка `docker compose stop` сохраняет тома. Не используйте `docker compose down -v` для рабочего экземпляра. Повторное поднятие с тем же проектом Compose должно использовать те же данные. Имена Compose-проекта и volumes входят в эксплуатационный паспорт экземпляра.

## Домен и HTTPS

Выбранное имя в зоне владельца направляется DNS-записью на сервер. Reverse proxy принимает HTTPS и отправляет трафик сайта, включая `/api/*`, в Next.js на loopback-порт. Так сохраняются единый Origin, подпись идентичности и обработка ошибок proxy. Адрес backend в `API_INTERNAL_URL` остаётся внутренним `http://api:8000`.

Пример HTTP-блока Nginx перед настройкой TLS. `afisha.example.org` заменяется согласованным доменом. Сертификат и перенаправление с HTTP на HTTPS настраиваются штатным механизмом выбранного reverse proxy.

```nginx
server {
    listen 80;
    server_name afisha.example.org;
    client_max_body_size 2m;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 100s;
    }
}
```

Этот блок сам по себе не включает HTTPS. До публикации должны работать действительный сертификат, HTTPS-origin в `.env`, Secure-cookie, постоянные ссылки, `/api/docs` и встраивание. Backend и БД не открываются публичными firewall-правилами ради этой настройки.

## Приёмка экземпляра

Проверьте каталог и карточку, запрос с моделью и принудительный fallback, планировщик, вход модератора, `/api/docs`, виджет на отдельной странице и одну копию бота. Мутирующие сценарии проверяются на изолированной тестовой БД. Отдельно проверьте резервное копирование и восстановление, актуальность источников и права на используемые материалы. Подробности в [эксплуатации](operations.md), [интеграциях](integrations.md) и [приёмке](acceptance.md).

ТЗ требует готовность чистого запуска за 10 минут. Проверка `compose config` не измеряет этот порог. Полный холодный запуск с замером, итоговая нагрузка на сервере и доступность выбранного домена фиксируются после реального развёртывания.
