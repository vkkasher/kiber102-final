# Конфигурация

Шаблон переменных находится в [`.env.example`](../.env.example). Создайте собственный `.env` для каждого окружения. Рабочие конфигурации, токены, пароли и ключи подписи исключены из Git и хранятся на сервере или в защищённом хранилище владельца. Проверка организаторами доступна через действующие сайт, API и бот. Для собственного запуска нужны отдельные доступы по [инструкции передачи](delivery.md). Пароли, токены и ключи не передаются через URL, клиентский JavaScript или аргументы запуска служб. После изменения переменных обновите окружение и перезапустите соответствующий сервис. Для Compose это пересоздание контейнера через `docker compose up -d`.

## Обязательные настройки

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | SQLAlchemy URL рабочей базы. В Compose API получает PostgreSQL URL из конфигурации сервиса |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL для Compose |
| `ADMIN_PASSWORD` | Пароль единственного локального администратора, если именованные аккаунты не настроены |
| `ADMIN_SESSION_SECRET` | Секрет подписи административных capabilities и серверных диалогов |
| `TRUSTED_PROXY_SECRET` | Общий секрет API, web и бота для подписи пользовательской идентичности, не менее 32 символов |
| `WEB_PUBLIC_URL` | Внешний URL сайта. Для production `https://…`, определяет публичные метаданные и флаг Secure у cookie посетителя |
| `WEB_URL` | Базовый URL сайта для интеграций и служебных ссылок |
| `CORS_ORIGINS` | Разрешённые точные Origins через запятую, без `*` |
| `API_INTERNAL_URL` | Адрес API из web-контейнера, в Compose `http://api:8000` |
| `API_URL` | Адрес API для бота и worker, в Compose `http://api:8000` |

Для нового экземпляра используйте разные случайные секреты. После установки Python-зависимостей `python scripts/configure.py --docker` создаёт недостающие секреты, сохраняя заданные значения. Для SQLite запускайте без `--docker`. Изменение URL базы не выполняет перенос данных.

`WEB_PUBLIC_URL` нужен при сборке web и во время работы. Compose передаёт его в `build.args` и `environment`. После смены внешнего Origin выполните `docker compose up --build -d`, чтобы пересобрать web с новым адресом. При сборке образа отдельно задайте `--build-arg WEB_PUBLIC_URL=https://ваш-домен`. Значение является публичным адресом, секреты через build arguments не передаются.

## Учётные записи

`ADMIN_ACCOUNTS_JSON` задаёт именованные аккаунты с полями `password_hash` и `role`. Роли `viewer`, `moderator`, `admin`. Хеш формирует `apps.api.app.security.hash_password`, открытые пароли в JSON не используются. Некорректная конфигурация закрывает вход. `WORKER_ADMIN_USERNAME`/`WORKER_ADMIN_PASSWORD` и `NOTIFICATION_ADMIN_USERNAME`/`NOTIFICATION_ADMIN_PASSWORD` нужны служебным процессам при раздельных аккаунтах.

## Telegram и уведомления

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Проектный токен бота. Без него Telegram-сеть не используется |
| `BOT_STANDBY` | Оставляет контейнер в ожидании без токена, в Compose включён |
| `BOT_STATE_PATH` | Путь SQLite-состояния бота, по умолчанию `.local/bot.sqlite` |
| `NOTIFICATIONS_ENABLED` | Включение транспорта уведомлений, по умолчанию `false` |

С одним токеном работает ровно один polling-процесс. Остановка локальной копии перед запуском на сервере обязательна. Созданная подписка и доставленное уведомление являются разными результатами. Браузерная подписка сама по себе не задаёт Telegram-получателя.

## Модель, источники и маршруты

Все `LLM_*`, параметры поставщиков и ограничения описаны в [интеграциях](integrations.md). `WORKER_INTERVAL_SECONDS` задаёт период сборщика, по умолчанию 3600 секунд. `SOURCE_ALLOWED_HOSTS` ограничивает домены, `SOURCE_DNS_MODE=system` оставляет системный DNS. Режим `doh` является отдельной настройкой для сред с подменой DNS. `SOURCE_VERIFICATION_MAX_AGE_HOURS` ограничивает свежесть проверок.

Для сверки Кассы.ру в `SOURCE_ALLOWED_HOSTS` нужны `ufa.kassy.ru` и `sterlitamak.kassy.ru`. Свежий шаблон уже содержит оба домена. При обновлении существующей конфигурации добавьте их, сохранив остальные разрешённые узлы. Если отдельно задана `SOURCE_ALLOWLIST`, backend использует именно её, поэтому оба домена должны присутствовать и в этом списке.

`SOURCE_ENABLE_STERLITAMAK_DEMO=1` включает только предусмотренный локальный демонстрационный сценарий. Он не является настройкой для промышленного сбора. Источники и правила их включения находятся в `apps/worker/sources.json`.
